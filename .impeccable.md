# GW2CraftingHelper - Design Context

## What this is

A Blish HUD overlay module (XNA/MonoGame, BitmapFont rendering - no CSS,
no web) that plans Guild Wars 2 crafting: what to craft, what to buy,
what it costs, using live GW2 API data and the player's own account
snapshot.

## Users

GW2 players planning crafts MID-GAME, overlay open on top of the running
game. They are: (a) time-sliced - reading between fights and TP trips, so
every glance must land; (b) fluent in GW2's own vocabulary (Trading Post,
disciplines, vendors) and in gw2efficiency's crafting tables, the density
reference they arrive from; (c) on screens the game already fills - the
module borrows space and must earn it.

## Personality

Quartermaster, not shopkeeper. Calm, exact, economical - the tone of the
game's own UI: information first, ornament only where GW2 itself puts it
(coin icons, quality colors, discipline icons). Never chatty, never
scolding; a status line reports, a tooltip explains, a dialog asks one
clear question.

## Principles

1. **Match the game.** GW2's UI conventions win ties: coin icons to the
   RIGHT of amounts, GW2 palette and iconography, GW2 names for GW2
   things.
2. **gw2e density, justified width.** Tables run full-width: the name
   column flexes and ellipsizes (full name on the tooltip), numerics,
   pills and actions right-anchor to the panel edge. No left-packed
   columns, no stranded dead space at any window width.
3. **Few sizes, real contrast.** One body size (16) does the work;
   hierarchy steps are at least 1.25x AND bolder - never
   smaller-and-grey. Section titles outrank column headers outrank body.
   A flat 14/16/18 ramp is the failure mode, not the system.
4. **Accents are budgeted (60-30-10).** Pill colors, warnings, and the
   rare highlight mean something because everything else is quiet. A
   color that appears everywhere is a color that says nothing.
5. **Every word earns its place.** Status lines are events in one
   grammar: a verb clause, a hyphen and its detail clause, an em-dash and
   a timestamp. Smart pluralization always; "(s)" never. IDs are internal
   - players see names, counts, and prices.
6. **Events are not state.** The status line reports what just happened.
   What the plan currently IS - how many decisions you have overridden,
   how many items you have ignored - is a persistent chip you can act on,
   not a sentence that scrolls away.
7. **Confirm only real losses.** A dialog appears when a click would
   destroy the user's manual decisions - and never otherwise. Primary
   actions stay one click; tooltips carry the warnings.
8. **Rhythm from spacing, not rules.** Varied vertical spacing groups
   related rows; separators are rare and structural.

## Hard constraints

Summarised here for tooling. The canonical, measured version - including
how the numbers were obtained - is
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) section 11, "Typography: the
measured type ramp".

- BitmapFont atlas: Menomonia 8-36 (bold at 8-24 and 36), reached via
  `ContentService.GetFont`, not only the five Blish defaults. Two entries
  are unusable and are recorded in `Services/TypeRampMetrics`:
  18-regular's space glyph collapses word gaps, and 22-regular is
  metrically a 24.
- Vertical constants are derived from measured glyph ink, not chosen.
  Two pixels of clearance under a descender, never one - Blish's
  non-integer UI-scale transform loses the last one.
- ASCII-only source; Unicode as escapes. An em-dash belongs only in
  rendered UI text, written as an escape.
- Some Blish controls (Checkbox, StandardButton, TextBox, Dropdown) are
  locked to Font14 - measure them in Caption, never restyle them.
- Item, currency and vendor IDs are never displayed.
- Layout arithmetic is Blish-free and unit-tested; only Views resolve
  fonts and colors.
